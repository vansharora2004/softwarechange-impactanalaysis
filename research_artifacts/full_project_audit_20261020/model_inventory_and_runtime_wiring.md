### A. Canonical Structural Graph Traversal Baseline

- **Implementation File:** [`backend/src/services/impactEngine.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/services/impactEngine.js)
- **Functions:** `analyzeImpact(changedIds, options)`, `analyzeImpactInMemory(changedIds, options)`, `analyzeImpactNeo4j(changedIds)`
- **Core Formula / Logic:**
  - Traverses structural relationships: `USES`, `DEPENDS_ON`, `TESTS` within $K = 2$ hops.
  - Hop 1 connections:
    - `TESTS` (incoming): Severity = `High`, Reason = `${neighborId} directly tests ${changedId}`
    - `DEPENDS_ON` (incoming): Severity = `High`, Reason = `${neighborId} depends directly (via injection) on ${changedId}`
    - `DEPENDS_ON` (outgoing): Severity = `Medium`, Reason = `${neighborId} is directly used (via injection) by ${changedId}`
    - `USES` (incoming): Severity = `High`, Reason = `${neighborId} directly references ${changedId}`
    - `USES` (outgoing): Severity = `Medium`, Reason = `${neighborId} is directly referenced by ${changedId}`
  - Hop 1 Filter: Direct outgoing `USES` to passive data components (`neighbor.type === 'Entity/Model' || neighbor.type === 'Other'`) are pruned from 1-hop impact.
  - Hop 2 connections:
    - Chained unidirectional paths: Incoming-Incoming (`LeafIn ➔ [r2] ➔ Mid ➔ [r1] ➔ Changed`) or Outgoing-Outgoing (`Changed ➔ [r1] ➔ Mid ➔ [r2] ➔ LeafOut`).
    - Incoming-Incoming 2-hop tests: `LeafTest ➔ [TESTS] ➔ Mid ➔ [r1] ➔ Changed`.
    - Prunes alternating paths (`Seed ➔ Mid 🡸 AltSibling`).
    - Excludes passive data components (`Entity/Model`, `Other`) as hop-2 leaf candidates.
  - Sorting & Ranking:
    - Primary: Impact Priority descending (`High` = 3, `Medium` = 2, `Low` = 1).
    - Tie-breaker: Component ID alphabetical (`a.id.localeCompare(b.id)`).
- **Unit & Contract Tests:**
  - [`backend/src/test/apiBaselineContractTests.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/test/apiBaselineContractTests.js): 5 passed, 0 failed.
  - [`backend/src/test/traversalConsistencyTests.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/test/traversalConsistencyTests.js): 25 passed, 0 failed.
- **Evaluation Harnesses:** Evaluated across `evalHarnessV3.js`, `historicalRerankerEvalHarness.js`, and `occpEvalHarness.js`.
- **Runtime API & UI:**
  - **Exposed on:** `POST /api/analyse-impact` and `POST /api/analyze-impact`.
  - **UI Integration:** **YES — this is the sole model invoked by the frontend Analyze Impact button.**
- **Status:** **ACTIVE & CANONICAL RUNTIME BASELINE.**

### B. V4 Historical Co-Change Reranker

- **Implementation File:** [`backend/src/services/structuralHistoryReranker.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/services/structuralHistoryReranker.js)
- **Functions:** `rerankCandidatesWithHistory(structuralCandidates, changedIds, historyCounts)`, `generateStructuralCandidatesInMemory(changedIds, graphData, maxHops)`, `analyzeStructuralHistoryImpact(changedIds, options)`
- **Core Formula / Logic:**
  - Preserves 100% of the candidate universe generated by `generateStructuralCandidatesInMemory`.
  - Calculates co-change support:
    $$\text{coChangeCount}(u) = \max_{s \in \text{changedIds}} \text{coChange}(s, u)$$
  - Sorting:
    1. `coChangeCount` descending (historically co-changed candidates promoted first).
    2. `structuralBaselineRank` ascending (candidates with identical or zero co-change retain their exact relative structural topological rank).
    3. Component ID alphabetical tie-break (`a.id.localeCompare(b.id)`).
  - Eliminates all arbitrary weights ($\alpha, \beta$) and arbitrary score thresholds ($\theta$).
- **Unit Tests:** [`backend/src/test/rerankerTests.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/test/rerankerTests.js): 40 passed, 0 failed.

### C. Model A — Context-Free Typed-Path Model

- **Implementation File:** [`backend/src/services/occp/occpModel.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/services/occp/occpModel.js)
- **Functions:** `trainPathModels(historicalEpisodes)`, `rankModelA_ContextIndependent(structuralCandidates, sourceId, candidatePathsMap, genericPathStats)`
- **Core Formula / Logic:**
  - Mined path statistics: For each path signature $p$, records $Pos(p)$ (instances where candidate was modified in the historical commit) and $Total(p)$ (instances where path $p$ was traversed).
  - Candidate Confidence:
    $$\text{confidence}(p) = \frac{Pos(p)}{Total(p)}$$
  - Selects the path with highest confidence among all paths connecting seed $s$ to candidate $u$.
  - Sorting:
    1. Positive support status (`hasSupport` first: $Pos(p) > 0$).
    2. Highest empirical confidence descending.
    3. Positive support count descending ($Pos(p)$).
    4. Total observations descending ($Total(p)$).
    5. Shorter hop distance ascending (`minHop`).
    6. Structural baseline rank ascending.
    7. Component ID alphabetical tie-break.
- **Unit Tests:** Covered in [`backend/src/test/occpTests.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/test/occpTests.js) (Test 5).
- **Evaluation Harnesses:** Evaluated as `Config 3` (`modelA_context_free`) in [`backend/src/evaluation/v5/occpEvalHarness.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/evaluation/v5/occpEvalHarness.js).
- **Runtime API & UI:** **OFFLINE RESEARCH ONLY.** Not wired into `api.js` or the UI.
- **Status:** **IMPLEMENTED & VERIFIED (Evaluation Baseline).**

### D. Model B — Operation-Conditioned Change Propagation (OCCP)

- **Implementation Files:**
  - [`backend/src/services/occp/operationClassifier.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/services/occp/operationClassifier.js)
  - [`backend/src/services/occp/pathSignature.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/services/occp/pathSignature.js)
  - [`backend/src/services/occp/occpModel.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/services/occp/occpModel.js)
- **Functions:** `classifyOperation(...)`, `buildPathSignature(...)`, `extractCandidatePathsFromSeed(...)`, `rankModelB_OCCP(...)`
- **Core Formula / Logic:**
  - Classifies source edit operation $o$ into 6 categories via unified diff regex analysis.
  - Extracts typed, direction-aware path signatures up to 2 hops.
  - Computes operation-conditioned empirical confidence:
    $$\text{confidence}(o, p) = \frac{Pos(o, p)}{Total(o, p)}$$
  - 4-Tier Hierarchical Fallback:
    - **Tier 1:** Operation-conditioned match ($Pos(o, p) > 0$).
    - **Tier 2:** Generic typed path match ($Pos(p) > 0$).
    - **Tier 3:** Historical co-change count ($\text{coChange}(s, u) > 0$).
    - **Tier 4:** Structural baseline topological rank.
- **Unit Tests:** [`backend/src/test/occpTests.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/test/occpTests.js): 16 passed, 0 failed.

### E. Reciprocal Rank Fusion (RRF)

- **Implementation File:** [`backend/src/services/occp/occpModel.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/services/occp/occpModel.js)
- **Functions:** `rankModelRRF_StructuralHistory(candidates, k = 60)`, `rankModelRRF_Composite(candidates, k = 60)`
- **Core Formulas:**
  - **Structural + History Fusion (Model 5):**
    $$RRF\_score(d) = \frac{1}{60 + rank_{struct}(d)} + \frac{1}{60 + rank_{hist}(d)}$$
  - **Composite Fusion (Model 6):**
    $$RRF\_composite\_score(d) = \frac{1}{60 + rank_{struct}(d)} + \frac{1}{60 + rank_{hist}(d)} + \frac{1}{60 + rank_{occp}(d)}$$
  - Constant $k = 60$ follows Cormack, Clarke & Buettcher (SIGIR 2009).
- **RPF Verification:** The acronym **RPF does not exist anywhere in executable code or tests**. It is verified to be a previous typographical error for RRF (Reciprocal Rank Fusion) or PRF (Precision/Recall/F1).
- **Unit Tests:** [`backend/src/test/occpTests.js`](file:///C:/yashika/STUDY/clg_project/software_change/backend/src/test/occpTests.js) (Section 6, assertions on $k=60$ and score calculation).
- **Evaluation Harnesses:** Evaluated as `Config 5` (`rrf_fusion`) and `Config 6` (`rrf_composite`) in `occpEvalHarness.js`.
- **Runtime API & UI:** **OFFLINE RESEARCH ONLY.**
- **Status:** **IMPLEMENTED & VERIFIED.**

- **Functions:** `analyzeContextAwareImpact(changedIds, options)`, `analyzeInMemory(changedIds, options)`, `MODEL_CONFIG`
- **Core Formula:**
  $$S = \alpha \cdot \text{baseInfluence} + \beta \cdot \text{contextInfluence}$$
  where:
  - $\alpha = 0.70$, $\beta = 0.30$
  - $\text{baseInfluence} = w_h \cdot \prod w_{\text{rel}}$, with $w_1 = 1.0, w_2 = 0.5$, $w_{\text{DEPENDS\_ON}} = 1.0, w_{\text{USES}} = 0.7, w_{\text{TESTS}} = 0.0$

  - $\text{historyWeight} = \min(\text{coChangeCount} / 20, 1.0)$
  - $\text{artifactWeight}$ derived from hardcoded architectural map (e.g., `Entity->Service` = 0.25).
